# Publication checklist

[简体中文](publication-checklist.md)

This document describes checks for product completeness, functional/performance reproduction, documentation, and privacy. The release contains standalone design and simulation sources, product SV, and bilingual documentation, with synthesis materials limited to summarized results.

## Product completeness

- Standalone top `GoldilocksBatchInversion` with all dependencies in the 10-file product list.
- The product list excludes simulation environments, reference-vector loaders, and verification-layer files.
- Product RTL contains no FPGA-vendor primitives or synthesis-domain integer division/remainder operations.
- Regenerated maximum-length-65,536 circuit bodies match the bundled product SV.

## Reproducible verification

- The per-element C reference is checked against independent Python modular inversion.
- Both product paths run eight test categories, including negative controls, reset recovery, backpressure, and malformed frames.
- Isolated latency and continuous sustained throughput are measured separately; utilization counts valid multiplication work.
- Complete maximum-configuration verification covers independent regenerated and bundled product builds.

Instructions are in [Quick reproduction](reproduction.en.md); test definitions and values are in [Performance metrics](performance.en.md).

## Documentation and distribution

- The default README.md is English, with the complete Chinese translation in README.zh-CN.md; every authored Markdown has a separate translation and reciprocal language links.
- All authored public Markdown documents have Chinese and English versions; English documents link to English documentation.
- Each Markdown opens with a content summary, and links to the same document use a consistent label within each language.
- The project uses the MIT License; the Release provides the complete repository source archive.

## Privacy and publication scope

Checks cover file contents, filenames, Git commit identity, and archive metadata. The payload contains no machine-specific absolute paths, caches, execution logs, account credentials, keys, private provenance digests, signatures, or internal maintenance records. It also excludes process libraries, original synthesis scripts/reports, and snapshots.

Mathematical constants and algorithmic test seeds are functional source data, not private credentials. Public commit identifiers and automatic download digests generated by Git/GitHub are normal platform metadata and are treated separately from private source-run provenance. Synthesis-material boundaries are described in [Synthesis summary](synthesis-summary.en.md).
